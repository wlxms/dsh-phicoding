# phicoding-level

## 等级律

> **依赖图上，若 A 依赖 B，则 A 的等级高于 B。高等级可以获取低等级的信息；低等级不得获取高等级的信息。**

**判据（可 grep）**：若 A 的源码中出现 B（字段类型、参数、返回值、或调用 B 的成员），则 B 的源码中不得出现 A。

必须是**源码引用**，不是可见性——C# 里所有 public 类型互相可见，那不是信息边界。

## 它与「依赖单向」的关系

依赖图无环 → 偏序存在 → 等级存在 → 「高可见低、低不可见高」自动成立。
A 与 B 互相引用 = 环 = 违规，所以**不需要额外的「同等级禁止横向依赖」规则**。

**但它不是重复。** 依赖单向说的是「不许成环」——一句禁令；等级律说的是「谁可以看谁」——一张图。**后半句才是有用的那半句**，因为它能判定一次具体访问是否合法。

**但「谁在谁上面」不需要一张全局的等级表。** 有一条**本地**判据，只看一条引用：

| 规则 | 只看什么 | 抓住什么 |
| --- | --- | --- |
| `0750-no-more-concrete` | 引用两端的类型各是什么档位 | 引用了某一档，又引用了同一族里更具体的一档 ⇒ 那个抽象点是装饰 |

**它只依赖这一条边本身**，不需要预先写一张全量等级表，也就不存在"表漏了一个类型，检查悄悄少判一块"这种事。

仍然存在一类它们抓不到的东西：**两个彼此无关、也没有继承关系的类型之间，那条边该不该有。** 这个只取决于设计意图，代码里读不出来——那是哲学法官在规划阶段要判的，不归检查器。

## 每个类型一个等级

**等级是设计时定的，不是从代码里算出来的。** 代码里读不出「修正层不该知道对象层」——那是判断，所以必须写下来。

**一个类型一行，一个不多、一个不少。**

写下来之后，机器能查三件事：

| 查什么 | 什么时候报 |
| --- | --- |
| **只许往下看** | 一个类型引用了等级比它高的类型 |
| **一个不多** | 名单里有、源码里没有 |
| **一个不少** | 源码里有、名单里没有 |

**后两条才是关键。** 少了它们：新加的类型不在名单里，机器就当它不存在——不报错、不报警、一切照绿，而那个类型**从来没被查过**。

等级定完，每个类型的**边界**也就明确了：**它能看见的是「等级不高于自己的那些类型」，其余一律看不见。**

> 这条不只管等级。**凡是靠名单圈定检查范围的地方，名单本身都要对着实际核一遍，两个方向都核。**

## 推与拉的不对称

低等级**可以**向高等级**推送**信号，但**不得**向其**拉取**信息。

| | 形态 | 是否产生向上的边 |
| --- | --- | --- |
| **推** | 发事件、报事实（「我诞生了」）、把值交出去 | **不产生**——发的人不关心谁接 |
| **拉** | 查询、分配、取配置 | **产生**——拿的人必须知道有谁提供 |

推有两种：**推事实**与**推请求**。两者都不取回值，都合法。

## 决策树：底层要依赖上层时

```
最低层说「我需要上层」
   │
   ├─ 第一步：这件事在它的完整内聚功能里吗？（核7）
   │    不在 → 拿掉它，交给上层编排。零依赖。
   │
   ├─ 第二步：这是「推」还是「拉」？
   │    推 → 事件 / 账本。零依赖。
   │
   ├─ 第三步：把上层这项能力下沉成契约，上层实现它
   │    最低层只依赖契约。注入面从「整个对象」缩到「契约面」。
   │
   └─ 第四步：构造链还是太深 → 声明式注入 [Require]
```

前三步是**设计**，第四步是**手段**。实际工程里绝大多数情况在第一步就没了。

**第一步的判据**：问「这件事不做，它的功能还完整吗？」完整 → 那不是它的职责，是被塞进来的。

## 第三步的收益，第二个比第一个重要

| 收益 | 说明 |
| --- | --- |
| 依赖无环 | 契约 ← 实现 ← 上层，等级图成立 |
| **注入面变窄** | 注入的不是整个管理器（可能 20 个方法），而是它的一项能力（2 个方法）——核5 的直接落地 |

**「注入太深」一半来自注入的是整个对象，而不是它的一项能力。**

**这不是收益，是本体系的硬要求：注入面只能是接口**——不得注入具体抽象（见 `phicoding` 的接口节）。第三步"下沉成契约"在落地时就是"抽一个能力接口"。

契约要**按能力分，不按对象分**。若契约在快速增殖，那不是等级问题，是管理器职责太杂——回到核7。

## 第四步：声明式注入

```csharp
[Require(typeof(IRoster<Unit>))]
public sealed class Weapon
{
    public Unit Aim() => Singleton.Get<IRoster<Unit>>().Find(IsHostile);
}
```

| | 构造注入 | 声明注入 |
| --- | --- | --- |
| 依赖写在哪 | 构造参数 | **类型上** |
| 构造链深度 | 沿链传递 | **零** |
| 等级图可读性 | 读签名 | grep `[Require]` |
| 缺依赖时 | 编译期 | 注册期失败 |

关键：**注册期校验让查找从「无约束」变回「有约束」**（设2）——它只允许拿到自己声明过的东西。

**代价**：依赖从构造函数签名里消失。**若没有生成等级图的工具，这一步的收益小于代价**——那就退回第三步，让签名说话。
