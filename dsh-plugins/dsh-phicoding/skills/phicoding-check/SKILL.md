# phicoding-check

## 哲学法官 · 关口一：审规划

规划在**执行之前**就要被审。**规划错了，执行越努力越远**——所以这道闸是阻塞的，不通过不许开工。

审规划的人必须是**独立上下文**，而且**不是写规划的人**。

| # | 判什么 | 打回的理由 |
| --- | --- | --- |
| 1 | **锚点可判吗** | 每条锚点能不能写成一句可机械判定的断言？写不成 → 那是愿望，不是锚点 |
| 2 | **三条链路齐吗** | 依赖链路（谁依赖谁、方向）、替换链路、拓展链路，缺一条就退回 |
| 3 | **度量给了吗** | 新增一个"解释"要写几处？超过"一个类型 + 一行登记" → 分层错了 |
| 4 | **主干知道实现吗** | 规划里主干有没有点到任何具体变体？点到即返工 |
| 5 | **有环吗** | 照着规划的依赖图看得出单向吗？看不出 → 规划不够具体 |
| 6 | **设计模式点名了吗** | 用了哪个、**为什么不是另一个**。两个都没说 → 退回 |
| 7 | **硬约束过一遍** | No Else / No Switch / 类型替代枚举 / 无环——规划里是否已经违反 |
| 8 | **留白列了吗** | 哪些需求没说清、要人来定 |
| 9 | **锚点有归属吗** | 每条锚点说得出"它将被哪条断言守住"吗？说不出 → 它的判据还没想清 |

**通过之后，锚点就成为执行的边界。** 执行期间要改锚点，等于改需求——回到设计者那里重走这道闸。

## 哲学法官 · 关口二：硬检查 + 软审查

**第一步永远是硬的**：先跑 `phicoding --root <项目>`。红了就是违规，直接打回，没有讨论空间。

检查器内部按 `meta → profile → soft` 三层跑。六个 meta 阶段（引用无环 → 引用等级 → 目录无环 → 目录归类 → 模块接口 → 命名 profile）递进执行；前一阶段红了，后面的 meta 与 profile/soft 都标 `BLOCKED`。profile 默认 `error`，项目可设 `profile.mode=warn` 降为警告；soft 只提示，不挡。`--only` 是单规则探针，绕过递进门。

**硬检查覆盖不到的，才由软审查做。** 硬检查只认结构与语法：

| 硬检查（检查器）管 | 软审查（智能体）管 |
| --- | --- |
| 主干有没有 `else` / `switch` / `enum` | 行为对不对——业务算得对不对、需求满足了没 |
| 命名粒度 | 主干找对了没——最小实现是不是真的最小 |
| 依赖有没有环、有没有向上边 | 作者漏了什么——它列的检查清单本身就是缺口地图 |
| 注释格式、命名粒度 | 分辨违规与实现选择——实现方式不同不等于违规 |

### 先判：标准符合性

硬检查的 `skip` 不是通过。工程没有 `Interfaces/` 时，`META_DIR_CLASS_02` / `META_SURFACE_05` / `META_DIR_CLASS_03` 不再一律 skip：它们会把**本次改动文件的共享目录根**推断成模块，再从接口位置判 `Interfaces/` 是否合规；只有改动范围里连目录根都推不出来才 skip。`META_SURFACE_02` 仍会检查抽象类（旧 `0700` 的不变量），具体类要等模块标准采用后才进入覆盖判据。
软审查仍必须先判：**这是“未采用标准”（软红），不是“不适用”**。

- 有项目级豁免记录（谁批 / 原因 / 范围 / 期限）→ 按豁免处理，不报违规；
- 没有豁免 → 要求迁移；**角色分层（Core / Variants / Load / Check）不能替代** `Interfaces/` / `Models/` / 概念实现目录；
- 逐层映射：`Core` → `Interfaces/` + `Models/`；`Variants` → 概念实现目录；`Load` / `Check` → 边界 / 组合根，移出模块或明确模块身份。

**软审报告第一行必须写“标准符合性”：通过 / 未采用（软红）/ 豁免（谁批、原因、范围、期限）。**

**软审查做四件事：**

写完之后把 **代码 + 需求原文 + 作者自己的报告**交给一个**独立上下文**的代理，并告诉它一句：

> **作者的结论是"声称"，不是证据。**

| # | 做什么 | 这一步抓什么 |
| --- | --- | --- |
| 1 | **独立复跑** | 不看作者结论，自己跑 `phicoding --root .`、自己跑工程测试、自己数数字。作者的"全绿"必须自己重现一次 |
| 2 | **变异测试** | **结构层**由框架自带的规则测试承担（业务项目不写、不跑）。**行为层要人做**：往核心不变量里注入一个坏值，看工程自己的测试会不会红 |
| 3 | **找作者没检查的东西** | 缺口比错误值钱：作者检查了 A、B、C——那 D 呢？**它列的检查清单，本身就是缺口地图** |
| 4 | **对账锚点** | 规划里的每条锚点，交付时有没有一条断言在守它？**锚点与断言对不上的地方，就是没被执行的地方** |

结论分**三类**写，不要混：

- **违规**——违反既有规则或项目级标准（含未采用接口模块且无豁免），有明确依据
- **规格留白**——需求没说清、作者必须自己判断的地方。这类不算作者的错，但要让需求方看到
- **实现选择**——编码与设计都合格，只是实现方式与你不同。**不要报成违规。**
  哲学不规定"怎么实现"（见 `phicoding` 的边界节），只留一条底线：**明显高开销的做法**才算违规
  ——热路径里调反射、该用字典处做线性遍历。除此之外，重算还是记增量、缓存还是不缓存，都是选择

## 十一条红线（由 phicoding 判）

| 红线 | 搜什么 | 违反 |
| --- | --- | --- |
| 有 `else` | `else` | 编4 |
| 有 `switch` | `switch` | 编5 |
| 抽象层有枚举 | `enum`（单个方法内的简单分支除外） | 设4 |
| 主干里的实现类型 | 主干源码里出现具体实现的类型名或实现字段 | 设2 |
| 有注释 | 除 `// [作者 日期] 原因` 追溯记录外的注释 | 编1 |
| 命名粒度太粗 | 一个名字一个词；`AAndB` 式并列；只有消歧才用多词 | 核4 |
| **命名不合范式** | 接口没有 `I`、枚举没有 `E`、特性没有 `Attribute`、异常没有 `Exception`、扩展类没有 `Extension(s)` | 核4 |
| 互相引用 | **整张依赖图无环**——不是逐对比对，主干内部同样适用。**两处豁免：自引用；以及一个类型与它自身嵌套类型之间的互指**（同一设计单元，不牵进第三方） | 核6 |
| **名字分派进主干** | **A** 主干（工厂除外）出现变体名的字面量分派。按用法判：名字在 `==` / `if` / `switch` 里 → 违规；在 `Add("...", new Xxx())` 里 → 允许 | 设2 |
| **变体不是类型** | **B** 需要被区分的变体没有对应的 CLR 类型，只剩一个数据行 | 规4 |
| **公开面不是接口** | `abstract class` 没有实现接口——抽象是公开面，公开面必须被接口覆盖 | 核5 + 接口根 |
| **引用越档** | A 引用了 B，又引用了同一族里比 B 更具体的类型：**接口** B 却引用了非接口子类；**抽象类** B 却引用了具体子类；**具体类** B 却引用了它的任何子类 | 设3 |

## 判定顺序

```
1. 具体实现图有环吗？    → META_REF_ACYCLIC_01；含 struct 的引用图环看 META_REF_ACYCLIC_02；纯接口 SCC 归软审
2. 契约纯吗？            → META_SURFACE_01（接口只引接口/value data/外部 PureDTO）、META_DIR_CLASS_04（record/class 纯数据；struct 一律数据）、META_SURFACE_03/META_SURFACE_04（模块数据概念有接口；DTO 隔离）
3. 行为类有接口吗？      → META_SURFACE_02；抽象类无模块也判，具体类要等模块标准；软审判“未采用标准”
4. 字段持有了具体实现吗？→ SOFT_DESIGN_01；装饰器持 IA 接口是合法的
5. 构造点收敛吗？        → SOFT_DESIGN_02；组合根/扩展/单一 owner
6. 有没有 else / switch？→ 有 → early return；表达不了 → 重新抽象
7. 有没有枚举？          → 方法之外的抽象用类型
8. 公开面最小吗？        → 参数、方法、字段，逐个数；**且公开面必须被接口覆盖**
9. 名字进主干了吗？      → 只有工厂可以出现名字分派（A）
10. 变体是类型吗？       → 逐个数；区分不了就是 B 没做到
11. 模块符合性？         → 没有 Interfaces/ 不是“不适用”；软审要求采用或登记豁免
```

**第 8 条的判据**：一个没人读的字段，和多余的公开参数是同一类问题——**最小信息不仅约束对外接口，也约束主干自己的数据形状**。

## 接口模块 · 目录分层（软性检查）

> 工程是否采用模块，先按关口二的“标准符合性”判；本清单只适用于已采用 / 已豁免的工程。

硬规则 `META_DIR_CLASS_02`–`META_DIR_CLASS_03` 判结构；下面这些机器判不了，归法官：

1. **模块根**：这个目录该不该是模块？按哪个角度拆？——项目决定，归软审。
2. **根实现 / 聚合根 / 组合根**：每个根实现独立判；组合根必须是**具体类**、在模块树外；根实现不得知道子模块。
3. **概念 vs 功能辅助**：接口是抽象概念还是辅助能力？辅助接口不该占概念目录、也不该被当成多接口类的 GCD。
4. **GCD**：一个类实现多个接口、没有唯一公共父接口时，落点看概念还是看辅助。
5. **对应目录**：抽象类放模块根，还是“对应概念实现目录”；目录名是不是最小命名（`IAdditivePass` → `AdditivesPass/` 或 `Additives/`）。
6. **数据枚举 vs 分派枚举**：接口引用的 `enum` 是纯取值，还是用分派取代了类型多态。
7. **外部边界与外部概念实现**：哪些是真正改不掉的外部事实、哪些其实是本模块实现；`<模块根>/<外部模块>/<概念>/` 的落点对不对。
8. **行为与锚点**：落地时既有测试 / 锚点是否守住（不属于规则检查）。

## 名字与类型：A 与 B

这两条必须成对，少一个体系就是残缺的。

| | 规则 | 单独存在会怎样 |
| --- | --- | --- |
| **A** | 主干（工厂除外）不得按名字分派 | 主干干净了，**但也没法区分种类了**——干净而无能 |
| **B** | 需要被区分的变体必须是**类型** | 能 `is` 了，但主干里可能还留着一堆 `if (name == "xxx")`——名字还是漏了 |

**B 是 A 的"可用性版本"**：A 说名字不许进主干，B 保证不进名字也仍然能区分。

### A 的判据（按用法，不按字面）

```
名字出现在"登记"的右边   Add("one-hand-sword", new OneHandSword());   → 允许（工厂）
名字出现在"分派"的左边   if (kind == "one-hand-sword")                 → 违规
```

从 config 抽出全部变体名，grep 主干；命中的位置**只允许在工厂里**。

**机械化配方——名字从哪里来，决定这条检查有没有用：**

| 抽名字的来源 | 好不好 |
| --- | --- |
| **工厂自己**（`Add("...", new Xxx())` 的登记名）、**数据表**里的名字 | ✅ 推导出来的，新加变体自动进检查 |
| 手写的 `'Sword','Axe','Plate'` 清单 | ❌ 要手工维护，而且**一定会漏** |

同一件事的两种做法，我都实测过：一版**从 JSON 抽名字回查主干**（对），另一版**硬编码 7 个类名**（错）。错的那版有两处永远抓不到——主干里明明写着 `Item.Slot => Body.register()`，而清单里**没有任何槽位名**；数据里写着 `"kind": "steel-sword"`，而**字符串不等于类名 `Sword`**。

> **检查的覆盖面必须从被检查的东西推导出来，不能手写。**

### B 的判据（逐个点名）

**每一个需要被区分的变体，都对应一个 CLR 类型。** 逐个数：`one-hand-sword` / `two-hand-sword` / `plate` / `ring` 各自有没有一个类型？

### B 的诊断动作，不是红线

"主干里写不出任何能用的 `is`"是一个**快速诊断动作**，用来判断 B 是不是没做到。

**它不是红线。** 纯多态的代码本来就不需要 `is`——每个虚调用自己做对的事，主干里一个 `is` 都不该有，那是好事。**没有 `is` 不违规**；违规的是"想区分却区分不了"，也就是变体不是类型。

## 第三条：静默覆盖

同一个失效形状会反复出现——**注册操作对重复键静默覆盖**：

```csharp
map[kind.Name] = kind;          // 注册表：冲突数据后者顶掉前者，不报错
codecs[kind]   = decode;        // 编解码注册：同上
$declares[$file] = $type;       // 检查器：循环里赋值，只有最后一个存活
```

三处后果不同，根因相同：**它把「冲突」变成了「后者获胜」**。在注册表里表现为数据互相顶掉，在检查器里表现为漏报——**两者都不报错**。

所以每个注册操作都要能回答两句：

1. **重复键会怎样？** 静默覆盖 → 改成显式失败，或显式声明覆盖语义。
2. **谁负责清空？** 进程级静态映射没有释放路径，就是顺序依赖与用例互染的来源。

## 常见违规与替换

| 违规 | 替换 |
| --- | --- |
| `if (a) { } else { }` | `if (a) return X; return Y;` |
| `switch (kind)` | 类型分发：`Slot<T>` / `Get<T>()` / 多态 |
| `enum DamageKind` | 空 struct 或 sealed class 作键 |
| 主干里 `if (kind == "atlas")` | 名字只留在工厂：`Add("atlas", new Atlas())`；主干拿到的已经是类型 |
| 种类做成数据行（`SlotKind`） | 升成类型层级 `sealed class OneHandSword : Weapon`，于是能 `is` |
| 固化层抽接口 | 固化写死，不抽接口；**"只有一个实现"不是删接口的理由**——接口是概念的最小承诺，行为类配接口是常态 |
| 具体抽象被注入 | 抽能力接口，注入接口不注入抽象（见 `phicoding` 的接口节） |
| `UnitManager` / `DamageService` | `Units` / `Damage` |
| 说明性注释 | 让代码自明；做不到就重新抽象 |
| 超长方法里一行空行都没有 | 按用途分成几组，组与组之间空一行；**切不出来 → 重新抽象**，空行只是分组的结果，不是分组的替代 |
| 多份状态副本 | 留一份真相，其余改为查询它 |

## 最小实现的自检问句

- 这个抽象代表最小实现的哪个环节？答不出 → 它不该存在。
- 拿掉它，核心功能还完整吗？完整 → 它不属于这里。
- 加一个变体，主干要改几行？非 0 → 分层错了。
- 这个字段、参数、方法，谁在读？没人 → 删。
- 新增一个解释要写几处？超过"一个类型 + 一行登记" → 分层错了。
- 需要按种类区分的地方，写得出 `is` 吗？写不出 → 变体不是类型（B 未满足）。

## 例外只有两条，且落在同一位置

| 例外 | 允许的位置 |
| --- | --- |
| 用 `object as T` 擦除类型 | 最低等级的框架内部 |
| 做高性能实现 | 最低等级的框架内部 |

**用户面不得使用任何一条。** 高频才优化，且要有依据：默认写最小实现，测出热路径再换内部实现；低频路径可以用性能换易读。

## 规则清单：红了怎么改

由 `phicoding` 机械判定，`phicoding --list --root <项目>` 可看全。**`1000` 以上的是项目自带规则**，每个项目的清单不同。

| 规则 | 守什么 | 红了怎么改 |
| --- | --- | --- |
| `PROFILE_STYLE_01` | 主干里没有 `else` | 改成 early return；**early return 表达不了就重新抽象**，而不是加 else |
| `META_NAMING_01` | 名字必须符合所属类别的范式：接口 `I` / 枚举 `E` / 特性 `Attribute` / 异常 `Exception` / 扩展类 `Extension(s)`。类别由结构认定，不由名字认定 | 改名。类别是结构判出来的，所以这条不会因为改名而自我实现 |
| `META_NAMING_02` | UE 家族前缀：沿基类链走到工程外那个名字，首字母是 A/U/F/S/T 时，本类型名字首字母必须相同。**只对 UE 工程生效**——工程里没有 UE 根类型（`AActor` / `UObject` / `FTableRowBase` …）就按不适用跳过 | 改名。判据是基类链，不是手写家族表；接口与枚举由 `META_NAMING_01` 管，这里不重复报 |
| `PROFILE_STYLE_02` | 注释只许是结构化追溯记录（全项目，不只主干）：`// [作者 日期 …] 原因`。括号里按空格切，字段表封闭，作者与项目一致，日期 `YYYY-MM-DD`，括号后必须有原因 | 要么删掉；要么写成 `// [wlxms 2026-10-18] 原因`。豁免写进括号：`waive=<规则id> why=<data/serialization/plumbing>` |
| `PROFILE_STYLE_03` | 超过 20 行的方法 / 类，内部至少有一行空行 | 按用途切成组，组与组之间空一行。**切不出组才是信号**——二十行还切不出边界，通常说明该重新抽象，而不是往中间插一行空白稀释它 |
| `META_SURFACE_01` | 接口只引用接口 / value data（struct·enum）/ 外部 PureDTO；模块内 class 数据只引其接口；不引用具体或抽象行为类 | 把接口签名里的具体实现换成接口；value data 可保留；外部配置 DTO 只作为已知数据结构引用；模块内 class 数据移到 `Config/` 或抽接口 |
