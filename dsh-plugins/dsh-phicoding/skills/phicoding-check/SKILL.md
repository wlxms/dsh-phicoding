# phicoding-check

## 哲学法官 · 关口一：审规划

规划在**执行之前**就要被审。**规划错了，执行越努力越远**——所以这道闸是阻塞的，不通过不许开工。

审规划的人必须是**独立上下文**，而且**不是写规划的人**。

| # | 判什么 | 打回的理由 |
| --- | --- | --- |
| 1 | **锚点可判吗** | 每条锚点能不能写成一句可机械判定的断言？写不成 → 那是愿望，不是锚点 |
| 2 | **三条链路齐吗** | 依赖链路（谁依赖谁、方向）、替换链路、拓展链路，缺一条就退回 |
| 3 | **度量给了吗** | 新增一个"解释"要写几处？超过"一个类型 + 一行登记" → 分层错了 |
| 4 | **主干知道实现吗** | 规划里主干有没有点到任何具体变体？点到即返工 |
| 5 | **有环吗** | 照着规划的依赖图看得出单向吗？看不出 → 规划不够具体 |
| 6 | **设计模式点名了吗** | 用了哪个、**为什么不是另一个**。两个都没说 → 退回 |
| 7 | **硬约束过一遍** | No Else / No Switch / 类型替代枚举 / 无环 / 无填充词命名——规划里是否已经违反 |
| 8 | **留白列了吗** | 哪些需求没说清、要人来定 |
| 9 | **锚点有归属吗** | 每条锚点说得出"它将被哪条断言守住"吗？说不出 → 它的判据还没想清 |

**通过之后，锚点就成为执行的边界。** 执行期间要改锚点，等于改需求——回到设计者那里重走这道闸。

## 哲学法官 · 关口二：硬检查 + 软审查

**第一步永远是硬的**：先跑 `phicoding --root <项目>`。红了就是违规，直接打回，没有讨论空间。

**硬检查覆盖不到的，才由软审查做。** 硬检查只认结构与语法：

| 硬检查（检查器）管 | 软审查（智能体）管 |
| --- | --- |
| 主干有没有 `else` / `switch` / `enum` | 行为对不对——业务算得对不对、需求满足了没 |
| 命名有没有填充词 | 主干找对了没——最小实现是不是真的最小 |
| 依赖有没有环、有没有向上边 | 作者漏了什么——它列的检查清单本身就是缺口地图 |
| 注释格式、字符串键越界 | 分辨违规与实现选择——实现方式不同不等于违规 |

**软审查做四件事：**

写完之后把 **代码 + 需求原文 + 作者自己的报告**交给一个**独立上下文**的代理，并告诉它一句：

> **作者的结论是"声称"，不是证据。**

| # | 做什么 | 这一步抓什么 |
| --- | --- | --- |
| 1 | **独立复跑** | 不看作者结论，自己跑 `phicoding --root .`、自己跑工程测试、自己数数字。作者的"全绿"必须自己重现一次 |
| 2 | **变异测试** | **结构层**已由 `phicoding --probe` 自动承担（每条规则必须只红自己）。**行为层要人做**：往核心不变量里注入一个坏值，看工程自己的测试会不会红 |
| 3 | **找作者没检查的东西** | 缺口比错误值钱：作者检查了 A、B、C——那 D 呢？**它列的检查清单，本身就是缺口地图** |
| 4 | **对账锚点** | 规划里的每条锚点，交付时有没有一条断言在守它？**锚点与断言对不上的地方，就是没被执行的地方** |

结论分**三类**写，不要混：

- **违规**——违反既有规则，有明确依据
- **规格留白**——需求没说清、作者必须自己判断的地方。这类不算作者的错，但要让需求方看到
- **实现选择**——编码与设计都合格，只是实现方式与你不同。**不要报成违规。**
  哲学不规定"怎么实现"（见 `phicoding` 的边界节），只留一条底线：**明显高开销的做法**才算违规
  ——热路径里调反射、该用字典处做线性遍历。除此之外，重算还是记增量、缓存还是不缓存，都是选择

## 十一条红线（由 phicoding 判）

| 红线 | 搜什么 | 违反 |
| --- | --- | --- |
| 有 `else` | `else` | 编4 |
| 有 `switch` | `switch` | 编5 |
| 抽象层有枚举 | `enum`（单个方法内的简单分支除外） | 设4 |
| 主干里的实现类型 | 主干源码里出现具体实现的类型名或实现字段 | 设2 |
| 有注释 | 除追溯注释外的注释 | 编1 |
| 填充词命名 | `Manager` `Service` `Helper` `Util` `Impl` | 核4 |
| 互相引用 | **整张依赖图无环**——不是逐对比对，主干内部同样适用。**两处豁免：自引用；以及一个类型与它自身嵌套类型之间的互指**（同一设计单元，不牵进第三方） | 核6 |
| **名字分派进主干** | **A** 主干（工厂除外）出现变体名的字面量分派。按用法判：名字在 `==` / `if` / `switch` 里 → 违规；在 `Add("...", new Xxx())` 里 → 允许 | 设2 |
| **变体不是类型** | **B** 需要被区分的变体没有对应的 CLR 类型，只剩一个数据行 | 规4 |
| **公开面不是接口** | `abstract class` 没有实现接口——抽象是公开面，公开面必须被接口覆盖 | 核5 + 接口根 |
| **引用越档** | A 引用了 B，又引用了同一族里比 B 更具体的类型：**接口** B 却引用了非接口子类；**抽象类** B 却引用了具体子类；**具体类** B 却引用了它的任何子类 | 设3 |
| **主干不自足** | 主干里声明的类型引用了主干之外的类型——那个外部类型就比主干高，不管隔了几层 | 核6 + 设4 |

## 判定顺序

```
1. 有没有环？            → 先看这个，环会让后面全部失效
2. 主干知道实现吗？      → 出现即返工，不必往下看
3. 有没有 else / switch？→ 有 → early return；表达不了 → 重新抽象
4. 有没有枚举？          → 方法之外的抽象用类型
5. 公开面最小吗？        → 参数、方法、字段，逐个数；**且公开面必须被接口覆盖**
6. 有没有多余的东西？    → 注释、填充词、没人读的字段
7. 名字进主干了吗？      → 只有工厂可以出现名字分派（A）
8. 变体是类型吗？        → 逐个数；区分不了就是 B 没做到
```

**第 6 条的判据**：一个没人读的字段，和多余的公开参数是同一类问题——**最小信息不仅约束对外接口，也约束主干自己的数据形状**。

## 名字与类型：A 与 B

这两条必须成对，少一个体系就是残缺的。

| | 规则 | 单独存在会怎样 |
| --- | --- | --- |
| **A** | 主干（工厂除外）不得按名字分派 | 主干干净了，**但也没法区分种类了**——干净而无能 |
| **B** | 需要被区分的变体必须是**类型** | 能 `is` 了，但主干里可能还留着一堆 `if (name == "xxx")`——名字还是漏了 |

**B 是 A 的"可用性版本"**：A 说名字不许进主干，B 保证不进名字也仍然能区分。

### A 的判据（按用法，不按字面）

```
名字出现在"登记"的右边   Add("one-hand-sword", new OneHandSword());   → 允许（工厂）
名字出现在"分派"的左边   if (kind == "one-hand-sword")                 → 违规
```

从 config 抽出全部变体名，grep 主干；命中的位置**只允许在工厂里**。

**机械化配方——名字从哪里来，决定这条检查有没有用：**

| 抽名字的来源 | 好不好 |
| --- | --- |
| **工厂自己**（`Add("...", new Xxx())` 的登记名）、**数据表**里的名字 | ✅ 推导出来的，新加变体自动进检查 |
| 手写的 `'Sword','Axe','Plate'` 清单 | ❌ 要手工维护，而且**一定会漏** |

同一件事的两种做法，我都实测过：一版**从 JSON 抽名字回查主干**（对），另一版**硬编码 7 个类名**（错）。错的那版有两处永远抓不到——主干里明明写着 `Item.Slot => Body.register()`，而清单里**没有任何槽位名**；数据里写着 `"kind": "steel-sword"`，而**字符串不等于类名 `Sword`**。

> **检查的覆盖面必须从被检查的东西推导出来，不能手写。**

### B 的判据（逐个点名）

**每一个需要被区分的变体，都对应一个 CLR 类型。** 逐个数：`one-hand-sword` / `two-hand-sword` / `plate` / `ring` 各自有没有一个类型？

### B 的诊断动作，不是红线

"主干里写不出任何能用的 `is`"是一个**快速诊断动作**，用来判断 B 是不是没做到。

**它不是红线。** 纯多态的代码本来就不需要 `is`——每个虚调用自己做对的事，主干里一个 `is` 都不该有，那是好事。**没有 `is` 不违规**；违规的是"想区分却区分不了"，也就是变体不是类型。

## 第三条：静默覆盖

同一个失效形状会反复出现——**注册操作对重复键静默覆盖**：

```csharp
map[kind.Name] = kind;          // 注册表：冲突数据后者顶掉前者，不报错
codecs[kind]   = decode;        // 编解码注册：同上
$declares[$file] = $type;       // 检查器：循环里赋值，只有最后一个存活
```

三处后果不同，根因相同：**它把「冲突」变成了「后者获胜」**。在注册表里表现为数据互相顶掉，在检查器里表现为漏报——**两者都不报错**。

所以每个注册操作都要能回答两句：

1. **重复键会怎样？** 静默覆盖 → 改成显式失败，或显式声明覆盖语义。
2. **谁负责清空？** 进程级静态映射没有释放路径，就是顺序依赖与用例互染的来源。

## 常见违规与替换

| 违规 | 替换 |
| --- | --- |
| `if (a) { } else { }` | `if (a) return X; return Y;` |
| `switch (kind)` | 类型分发：`Slot<T>` / `Get<T>()` / 多态 |
| `enum DamageKind` | 空 struct 或 sealed class 作键 |
| 主干里 `if (kind == "atlas")` | 名字只留在工厂：`Add("atlas", new Atlas())`；主干拿到的已经是类型 |
| 种类做成数据行（`SlotKind`） | 升成类型层级 `sealed class OneHandSword : Weapon`，于是能 `is` |
| 固化层抽接口 | 固化写死，不抽接口；**"只有一个实现"不是删接口的理由**——接口是公开面，抽象配接口是常态 |
| 具体抽象被注入 | 抽能力接口，注入接口不注入抽象（见 `phicoding` 的接口节） |
| `UnitManager` / `DamageService` | `Units` / `Damage` |
| 说明性注释 | 让代码自明；做不到就重新抽象 |
| 多份状态副本 | 留一份真相，其余改为查询它 |

## 最小实现的自检问句

- 这个抽象代表最小实现的哪个环节？答不出 → 它不该存在。
- 拿掉它，核心功能还完整吗？完整 → 它不属于这里。
- 加一个变体，主干要改几行？非 0 → 分层错了。
- 这个字段、参数、方法，谁在读？没人 → 删。
- 新增一个解释要写几处？超过"一个类型 + 一行登记" → 分层错了。
- 需要按种类区分的地方，写得出 `is` 吗？写不出 → 变体不是类型（B 未满足）。

## 例外只有两条，且落在同一位置

| 例外 | 允许的位置 |
| --- | --- |
| 用 `object as T` 擦除类型 | 最低等级的框架内部 |
| 做高性能实现 | 最低等级的框架内部 |

**用户面不得使用任何一条。** 高频才优化，且要有依据：默认写最小实现，测出热路径再换内部实现；低频路径可以用性能换易读。

## 规则清单：红了怎么改

由 `phicoding` 机械判定，`phicoding --list --root <项目>` 可看全。**`1000` 以上的是项目自带规则**，每个项目的清单不同。

| 规则 | 守什么 | 红了怎么改 |
| --- | --- | --- |
| `0100-no-else` | 主干里没有 `else` | 改成 early return；**early return 表达不了就重新抽象**，而不是加 else |
| `0200-no-switch` | 主干里没有 `switch` | 抽成多态：一种情况一个类型 |
| `0300-no-enum` | 主干里没有 `enum` | 枚举换成抽象类型 + 子类（见 `phicoding-shape` 的按类型索引定理） |
| `0400-no-filler` | 命名里没有 Manager / Service / Helper / Util / Impl | 用职责本身命名；**说不清职责 = 职责没切开** |
| `0500-comments` | 注释只许是追溯注释（全项目，不只主干） | 要么删掉，要么写成 `// 作者 - 日期 : 内容`（作者要与项目作者一致） |
| `0600-no-static-state` | 主干里没有**可变的**静态状态。静态方法 / `const` / `static readonly` 的不可变值都合法；`static readonly` 的集合若按实例类型索引，仍算外挂账本 | 状态跟着实例走；真要一个进程级容器（Unity、程序入口），把它声明进 `staticStateOwners`，并让容器自己能被枚举 |
| `0650-string-key-scope` | 字符串当键只允许出现在一个类型里 | 换成按类型索引 |
| `0700-abstract-has-interface` | 每个抽象至少实现一个接口 | 给这个抽象抽一个能力接口让它实现。**不是删掉抽象**——接口是最小公开面，抽象配接口是常态 |
| `0750-no-more-concrete` | 引用的具体度不越档 | 把那个更具体的引用换回 B 挡位上的类型：接口档换接口、抽象档换抽象。**不是删掉 B 的引用** |
| `0800-no-cycle` | 依赖无环（自引用、以及类型与其自身嵌套类型之间的互指不算） | 见 `phicoding-level` 的四步决策树 |
| `0900-trunk-is-self-contained` | 主干只引用主干里声明的类型 | 把外部类型下沉成主干里的契约；或把这段职责移出主干。见 `phicoding-level` 的四步决策树 |
| `1000-` 以上 | 项目自带，看规则文件头注释 | — |
