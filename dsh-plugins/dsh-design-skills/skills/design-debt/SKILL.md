# design-debt

`ponytail` 已经定了标记约定：**故意简化的地方用 `ponytail:` 注释记下天花板与升级路径**。

```
# ponytail: 全局锁，吞吐上来了改成按账号锁
```

本技能做两件 `ponytail-debt` 不做的事：把散落的标记收成台账，并**为每条补上"动哪里"**。

## 为什么补"动哪里"

`ponytail:` 记的是**已知天花板**（为什么现在可以这样），但没说**将来改的时候落点在哪**。而落点正是设计里最贵的信息：没有它，接手的人得重新把整条链路读一遍才知道该改哪儿。

所以每条账目三列：

```markdown
| 位置 | 天花板 / 为什么现在可以 | 将来要动它，动哪里 |
| --- | --- | --- |
| Engine/ResourceUpdater.cs:88 | 全局锁，单线程够用 | 锁粒度：StagedContent 的槽位；改按槽位加锁，主干不动 |
| Host/Impl.cs:120 | O(n²) 扫描 | 换成索引；接口不变，属实现替换 |
```

## 扫描规则

1. 搜 `ponytail:`、`缝:`、`TODO(seam)` 等标记（沿用仓库既有约定）。
2. 分类：**可触发性** —— 什么时候会撞到它（吞吐 / 规模 / 平台 / 某个未来需求）。
3. 排序：**最可能先撞到的排前面**，不是按文件顺序。
4. 缺"动哪里"的条目，就地去代码里定位缝的位置再补；补不出来的，**那条缝其实没标记成功**，标出来。

## 不要做的

- 不把缝报成缺陷（那是 `design-audit` 的活）。
- 不建议"顺手清掉"。缝是**有意的取舍**；要撤必须走 `design-gain` 的判据。
- 不把 TODO 里所有东西都算进来——只收**设计层面的简化**，不收待办杂事。
