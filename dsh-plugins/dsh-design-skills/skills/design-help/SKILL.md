# design 速查

## 一条法则

**先尽量不写；不得不写时，让主干不知道变体的名字。**
量归 `ponytail`，形归本体系。

## 技能

| 技能 | 何时加载 |
| --- | --- |
| `design` | 任何改结构的编码任务。总入口与路由 |
| `design-contract` | 写设计卡 / 决定抽不抽 / 定缝的形状 |
| `design-ladder` | 规划用例 / 验证 / 判断抽象成没成 |
| `design-audit` | 评审一段改动或一个仓库的过度抽象 |
| `design-debt` | 盘账：哪里有故意留的缝，将来动哪里 |
| `design-gain` | 判断一个抽象该留、该改、还是该撤 |
| `design-help` | 本卡（仅用户可调用） |
| `ponytail` | 量：要不要写、写多少（独立包） |

## 四个元规则

- **准入律** — 能指名 ≥2 个已存在或已承诺的变体才抽象；指不出 → 写最简实现 + 标记缝。
- **无知律** — 主干源码里不得出现变体的名字。判据：扩展它，要不要改主干？
- **可证伪律** — 真加一次变体 #2 并测主干字节；且必须与运行时断言配对。
- **归类律** — 一切红灯先归类：同轴新变体 / 正交新轴 / 用例集扩张。未归类就动手 = 唯一的失败。

## 三档强度

`lite`（点出更懒的替代）· `full`（默认，全套执行）· `ultra`（先质疑需求本身，删优于加）。

切换：`/design lite|full|ultra`。关闭：`停用 design` / `normal mode`。

## 常用口令

- 「这块该不该抽」→ `design-contract` 的准入律
- 「主干会不会被改」→ 声明主干边界 + 比 SHA256
- 「这个抽象该留吗」→ `design-gain`
- 「这段代码是不是过度设计」→ `design-audit`
- 「哪里有坑」→ `design-debt`
