# design

两层合成一条法则：**先尽量不写；不得不写时，让主干不知道变体的名字。**

- **量**归 `ponytail`。它的梯子决定要不要写、写多少。本技能不重复梯子——先加载 `ponytail`，或者按下节那一行底线走。
- **形**归本体系。当你必须动结构时，从这里往下路由。

## 与 ponytail 的边界

`ponytail` 管**建什么**，本体系管**怎么切**。两者都不管你怎么说话。

若 `ponytail` 未加载而你要爬梯子，底线是：**需要存在吗 → 仓库里已有吗 → 标准库 → 原生平台 → 已装依赖 → 一行 → 最小代码。**

## 四个元规则（违反即返工）

**准入律** — 只有能指名 **≥2 个已存在或已承诺**的具体变体，才做抽象。"以后可能需要"不算。指不出来 → **写最简实现 + 标记缝**（用 `ponytail:` 注释记下天花板与升级路径）。这是合法结论，不是偷懒。

**无知律** — 主干不得在**源码**里知道变体的名字。注册表与多态满足它；枚举加 switch、变体专属字段、主干里的 `if (kind === 'x')` 违反它。
判据：**扩展它，要不要改主干？**

**可证伪律** — 真加一次「变体 #2」并测主干改动，而且**必须与运行时断言配对**：主干 0 行 ≠ 性质成立。

**归类律** — 一切红灯（要动主干 / 主干里出现变体名 / 两个分支流程图形状不同）先归类：同一变轴上的新变体 / 正交的新变轴 / 必须支持的用例集扩张。**未归类就动手 = 唯一的失败。**

## 三步流程

1. **切分 · 定单位与契约** — 判据：问「我要如何操作它」。有答案 → 它是一个对象（可递归）；没答案 → 叶子。一个对象 = 一份契约 + 它的消费者集合。
2. **必要性 · 定成员** — 逐条问：**失效后流程能否完成，或能否在流程内自愈？** 不能 → 必要，且成为主干不变量。
3. **变化压力 · 定缝** — 对每个元素问两轴，对每个接口问来源。稳定 → 写死；易变 → 插槽或注册表。

然后对每个质量集成员递归重走一遍。细节在 `design-contract`。

## 路由

| 你现在要做的事 | 加载 |
| --- | --- |
| 写设计卡 / 决定这块该不该抽 / 定缝的形状 | `design-contract` |
| 规划用例 / 验证改动 / 判断抽象成没成 | `design-ladder` |
| 评审一段改动或一个仓库有没有过度抽象 | `design-audit` |
| 接手别人代码，想知道哪里有缝 | `design-debt` |
| 判断一个抽象该留还是该撤 | `design-gain` |
| 速查 | `design-help` |

## 强度

| 档 | 行为 |
| --- | --- |
| **lite** | 照做，但用一行点出更懒的替代，由用户选 |
| **full**（默认） | 梯子与四规则都执行；最短 diff，最短解释 |
| **ultra** | 准入律极端化：先质疑需求本身，删优于加 |

关闭：`停用 design` / `normal mode`。默认 full，逐轮持续生效。
